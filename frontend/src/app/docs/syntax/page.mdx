# Basic Syntax

VizLang is a concise, line-oriented chart description language. Files are typically a short sequence of property lines, optional variable/array assignments, and a `data:` section (either inline or block style).

## File shape (concrete)

A common, minimal file looks like this:

```vizl
chart: bar
title: My Awesome Chart
x: Category
y: Value

data:
"A", 10
"B", 20
```

Rules to keep in mind:

- Order is flexible: properties/assignments may appear before or after one another, but `data:` indicates the start of a row-based block when present.
- Blank lines are ignored.
- Whitespace around separators (`:`, `=`, `,`) is allowed and trimmed.

## Properties

Properties are `key: value` pairs. Common keys:

| Key         | Purpose                                                          |
| ----------- | ---------------------------------------------------------------- |
| `chart`     | Required. One of: `line`, `bar`, `scatter`, `pie`.               |
| `title`     | Optional display title (string or variable).                     |
| `x`         | Optional X-axis label (string).                                  |
| `y`         | Optional Y-axis label (string).                                  |
| `null_fill` | Missing-value strategy (`zero`, `mean`, `prev`, `next`, `skip`). |
| `colors`    | Optional palette (array of CSS color strings)                    |

Unknown property keys are ignored by the renderer but may be used by tooling.

## Data shapes and formats

VizLang accepts two styles for data:

- Block-style rows (preferred for multi-line human-edited data):

```vizl
data:
"Jan", 100
"Feb", 150
"Mar", 125
```

- Inline array-of-pairs (compact, copy/paste friendly):

```vizl
data: [["Jan", 10], ["Feb", null], ["Mar", 20]]
```

Notes:

- Rows are parsed as `x, y` pairs. `x` can be string or number; `y` should be numeric or `null`.
- When using inline arrays, nested arrays are allowed (e.g., array-of-pairs or matrix shapes).
- Strings containing commas or leading/trailing whitespace should be quoted with double quotes.

## Strings, quoting, and escaping

- Strings must use double quotes (`"`); unquoted identifiers beginning with a letter are treated as variable names or identifiers.
- To include a double quote inside a string, escape it using `\"`.

Example with quotes and commas:

```vizl
data:
"New York, NY", 120
"Los Angeles", 95
```

## Comments and block comments

Supported comment styles:

```vizl
// single-line comment
/* multi-line block comment */
# legacy single-line
```

Block comments preserve line counts so that error messages keep correct line numbers.

## Assignments and variables in expressions

- Assignment syntax: `NAME = EXPRESSION`.
- Optional typed assignments: `int name = ...`, `float name = ...`, `string name = ...`, or typed arrays like `int[] arr = [...]`.
- Variables can be used in later expressions, chart properties, and data rows.

Expression examples (see `variables` page for more):

```vizl
base = 100
growth = 1.2
title: "Revenue " + 2026
myData = [["A", base], ["B", base * growth]]
```

## Function calls and helpers

VizLang provides small helper functions evaluated at parse time. One example is `combine(arr1, arr2)` which pairs two arrays into an array-of-pairs. See the Arrays docs for details.

## Parsing edge cases and tips

- If a value is neither a quoted string nor a recognized literal (number/null) and it matches a variable name, the variable's value is used.
- When `data:` is present as a block, the parser reads subsequent lines as data rows until a non-data line appears.
- Use `null` (or `None`) to represent missing values; choose a `null_fill` strategy to control how missing `y` values are handled.

## Quick checklist (copyable)

```vizl
chart: line
title: My Chart
myVar = 10
data: [["A", myVar], ["B", 20]]
```

Read the `Arrays`, `Variables`, and `Nulls` pages for deeper examples.
