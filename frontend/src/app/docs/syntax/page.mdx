# Basic Syntax

VizLang is line oriented. Most files are a short mix of properties, variable definitions, and a data section.

## File shape

Most documents follow this pattern:

1. Declare the chart type and optional labels.
2. Define any variables or arrays you need.
3. Provide data with either a block or an inline array.

```vizl
chart: bar
title: "My Awesome Chart"
x: "Category"
y: "Value"
```

## Properties

Properties use the `key: value` format.

| Key         | Description                                                           |
| ----------- | --------------------------------------------------------------------- |
| `chart`     | Required. Chooses the chart type: `line`, `bar`, `scatter`, or `pie`. |
| `title`     | Optional chart title.                                                 |
| `x`         | Optional horizontal axis label.                                       |
| `y`         | Optional vertical axis label.                                         |
| `null_fill` | Optional missing-value strategy.                                      |
| `colors`    | Optional palette for chart colors.                                    |

## Data Block

The `data:` keyword starts a row-based data block. Each row is read as one data point.

```vizl
data:
"Jan", 100
"Feb", 150
"Mar", 125
```

Use a data block when the rows are easier to read than a nested array.

Examples that work well with block data:

```vizl
chart: bar
title: Weekly Orders

data:
"Mon", 12
"Tue", 18
"Wed", 15
"Thu", 21
"Fri", 25
```

```vizl
chart: line
title: Sensor Readings

data:
"08:00", 18.2
"09:00", 18.6
"10:00", 19.1
"11:00", 20.0
```

## Inline data

You can also provide data directly as an inline array or a variable that contains one.

```vizl
myData = [["Q1", 340], ["Q2", 520]]
data: myData
```

```vizl
data: [["Jan", 10], ["Feb", null], ["Mar", 20]]
```

Inline data is useful for short examples, generated output, and charts that need to stay compact.

It is also the best option when you want the entire chart definition to fit in a small code sample or documentation snippet.

## Comments

VizLang supports three comment styles:

```vizl
// single-line comment
/* block comment */
# legacy comment
```

Comments are ignored by the renderer and can be used freely for notes or section breaks.

Good comment uses include:

```vizl
// data arrives from an external API
// this section uses a fallback for null values
```

```vizl
/*
Multi-line notes are useful when you want
to explain a longer example.
*/
```

## Example

```vizl
chart: bar
title: Quarterly Revenue

x: quarter
y: revenue

// Inline array-of-pairs keeps the file short.
data: [["Q1", 120], ["Q2", 150], ["Q3", 170], ["Q4", 200]]
```

## Reference checklist

- `chart:` picks the chart type.
- `title:` adds a heading.
- `x:` and `y:` label the axes.
- `data:` begins a row block or accepts an inline array.
- `colors:` sets the palette.
- `null_fill:` controls missing-value handling.
