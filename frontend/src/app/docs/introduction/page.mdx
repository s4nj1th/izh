# Introduction

VaraiX is a focused, line-oriented chart description language intended for authors and automation pipelines that need compact, deterministic SVG charts. A single `.vix` file describes exactly one chart; the parser and renderer aim to ensure the same input always produces the same SVG output.

The language is intentionally small and opinionated: it provides the primitives most often required for simple charts (titles, axes labels, series data, palettes, and null-handling policies) while keeping parsing semantics predictable and fast.

## Philosophy and goals

- Concise: keep chart specs short and readable by humans.
- Deterministic: identical input → identical output across platforms and runs.
- LLM-friendly: the line-oriented, key/value layout is easy to synthesize and validate.
- Portable: output SVG works in browsers, static sites, slides, and PDFs.

## File anatomy (what a `.vix` looks like)

- Top-level key/value pairs: `chart: <type>`, `title: ...`, `x: ...`, `y: ...`.
- Assignments: `NAME = EXPRESSION` for variables, typed or untyped.
- `data:` either starts a block of CSV-like rows or accepts an inline array variable/literal.

Minimal example (inline array):

```vix
chart: line
title: Monthly Revenue

myData = [["Jan", 12], ["Feb", 19], ["Mar", 15], ["Apr", 22]]
data: myData
```

Block-style data example (alternate form):

```vix
chart: bar
title: Quarterly Revenue

x: quarter
y: revenue

data:
"Q1", 120
"Q2", 150
"Q3", 170
"Q4", 200
```

## Key concepts (quick reference)

- Arrays: fixed-size, evaluated at parse time. Support list literals, inclusive ranges (`[1..5]`), and simple comprehensions.
- Typed arrays and scalars: `int`, `float`, `string` annotations enable coercion and clearer intent.
- Nulls: `null` or `None` are supported; use `null_fill:` to control behavior (`zero`, `mean`, `prev`, `next`, `skip`).
- Colors: `colors:` accepts an inline palette or a palette variable; the renderer uses palettes to color series/slices.

## Using VaraiX with automation and LLMs

VaraiX is intentionally small to make programmatic generation easier. If you generate `.vix` files from code or LLMs:

- Validate the presence of required keys: `chart` and `data` (or a data variable).
- Prefer inline arrays for compactness and portability.
- Use `null_fill` explicitly if null-handling matters for your chart.

Example snippet you might generate from a script:

```vix
chart: scatter
title: Sample Points

myPoints = [[1, 2], [2, null], [3, 4]]
null_fill: prev
data: myPoints
```

## Troubleshooting & tips

- If a chart looks wrong, verify your `data:` structure: bar/pie expect categorical X values or ordinal indices; line charts accept numeric or categorical X with proper spacing.
- When using `skip` for `null_fill`, be mindful that x-axis labeling and spacing may change because points are removed.
- For predictable colors supply a palette with at least as many colors as data points for pie/bar charts.
